# Historias de éxito con texto y multimedia

Objetivo: relatos sobre experiencias con los productos, con texto opcional cuando hay multimedia, imágenes, videos subidos y enlaces de video. No testimonios inventados ni centrados por defecto en el software.

Arquitectura: D1 para historias y adjuntos, R2/document_files para archivos dentro de la cuota actual. Admin gestiona borradores, publicación y archivo. Clientes y asesores consultan únicamente historias publicadas y medios completos con autorización registrada. Texto plano y multimedia bajo accesos vigentes; sin enviar testimonios al chatbot.

- [x] Repositorio, esquema y pruebas de publicación textual/multimedia, permisos y paginación.
- [x] API de gestión y carga reutilizando transferencia multipart; reproducción y archivos protegidos.
- [x] Formulario administrativo, plantillas identificadas como ejemplos y catálogo centrado en experiencias con productos.
- [x] Validación completa, revisión, publicación privada y respaldo Git.

Decisiones: hasta6 adjuntos, imágenes JPG/PNG/WebP hasta10MB y MP4/WebM hasta200MB; todos comparten los500MB existentes. Plantillas editables internas en vez de publicar experiencias ficticias. Relación opcional con varios productos; autor puede ser nombre o iniciales. Guardar borrador no exige texto ni autorización; publicar exige relato o medio completo y confirmación de permiso para compartir. Mantener verde/marfil, navegación independiente y búsqueda/paginación.
